# github_organization_teams (Resource)

Resource to authoritatively manage which teams exist in a GitHub organization.

This resource lists the teams that may exist in the organization and deletes every other team on apply. It does not create teams; manage those with [`github_team`](team) and reference their slugs, so the teams are created before this resource is applied. Applying fails if a listed team does not exist, or if a listed team is nested under a team that is not listed, because deleting a parent team also deletes its child teams.

!> Every team not listed is deleted on apply, together with its members and repository access. A team created with `github_team` but left out of `team_slugs` is deleted and then created again on each apply.

The provider token must be able to [delete teams](https://docs.github.com/en/rest/teams/teams#delete-a-team) in the organization, which needs organization owner rights; a classic token needs the `admin:org` scope.

When this resource is destroyed it is only removed from the Terraform state; no teams are deleted. Terraform shows a warning when this happens.

## Example Usage

```terraform
resource "github_team" "maintainers" {
  name = "maintainers"
}

resource "github_team" "contributors" {
  name = "contributors"
}

resource "github_organization_teams" "example" {
  team_slugs = [
    github_team.maintainers.slug,
    github_team.contributors.slug,
  ]
}
```

## Import

This resource is imported by the organization name, which must match the provider's `owner`.

Import is supported using the following syntax:

In Terraform v1.5.0 and later, the [`import` block](https://developer.hashicorp.com/terraform/language/import) can be used with the `id` attribute, for example:

```terraform
import {
  to = github_organization_teams.example
  id = "my-org"
}
```

The [`terraform import` command](https://developer.hashicorp.com/terraform/cli/commands/import) can be used, for example:

```shell
terraform import github_organization_teams.example my-org
```
