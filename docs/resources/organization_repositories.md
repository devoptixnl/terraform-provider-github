# github_organization_repositories (Resource)

Resource to authoritatively manage which repositories are active in a GitHub organization.

This resource lists the repositories that stay active in the organization and archives every other active repository on apply. Repositories are never deleted or unarchived. It does not create repositories; manage those with [`github_repository`](repository) and reference their names, so the repositories are created before this resource is applied. Applying fails before anything is archived if a listed repository does not exist.

The plan shows the repositories the apply will archive in `repositories_to_archive`, including on the first apply. A repository created after the plan but before the apply is not in that list and is archived as well when it is not listed.

A listed repository that is already archived stays archived; unarchive it with `archived = false` on its `github_repository` resource. Archived repositories that are not listed are ignored.

!> Every active repository not listed is archived on apply, which makes it read-only. Resources that change an archived repository, such as files, labels, webhooks or collaborators, fail on their next apply. A repository managed with `github_repository` but left out of `repository_names` is archived on one apply and unarchived by its `github_repository` resource on the next, so build `repository_names` from the same map as the `github_repository` resources, as in the example. Use one instance of this resource per organization; two instances archive each other's repositories.

Only repositories the provider token can see are enforced. The token must be able to [list the organization's repositories](https://docs.github.com/en/rest/repos/repos#list-organization-repositories) and [update](https://docs.github.com/en/rest/repos/repos#update-a-repository) every one of them, which needs admin access to each repository; a classic token needs the `repo` scope.

When this resource is destroyed it is only removed from the Terraform state; no repositories are archived. Terraform shows a warning when this happens.

## Example Usage

```terraform
locals {
  repositories = {
    website = "Company website"
    infra   = "Infrastructure as code"
  }
}

resource "github_repository" "this" {
  for_each = local.repositories

  name        = each.key
  description = each.value
}

resource "github_organization_repositories" "example" {
  repository_names = [for repo in github_repository.this : repo.name]
}
```

## Schema

### Required

- `repository_names` (Set of String) Names of the repositories that may stay active in the organization. Any other repository is archived.

### Read-Only

- `id` (String) The ID of this resource.
- `repositories_to_archive` (Set of String) Active repositories that are not listed and will be archived on the next apply. Shown in the plan; empty after apply.

## Import

This resource is imported by the organization name, which must match the provider's `owner`.

Import is supported using the following syntax:

In Terraform v1.5.0 and later, the [`import` block](https://developer.hashicorp.com/terraform/language/import) can be used with the `id` attribute, for example:

```terraform
import {
  to = github_organization_repositories.example
  id = "my-org"
}
```

The [`terraform import` command](https://developer.hashicorp.com/terraform/cli/commands/import) can be used, for example:

```shell
terraform import github_organization_repositories.example my-org
```
